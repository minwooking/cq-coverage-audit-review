# Deviations from PLAN.md (addendum 36)
1. **F question file.** The brief said to generate a per-domain pipeline-side question file from the frozen bank if F needs one. The Brick build used one fixed file (`eval/competency_questions.json`) and no generating tool, and `build_domain.sh` refuses bank-derived files (leak into construction). All three F builds therefore use the same fixed file as the Brick build (PLAN 36.5, stated before any call). The banks were not given to construction.
2. **Domain cells include unpaired A or B cells.** `build_jobs.py` first kept only questions with both A and B; this was widened before any new score was read, because A->F and B->F need A-only and B-only cells (PLAN 36.2 "every A/B cell"). 372 A/B cells (Brick 158, domains 214), 105 F cells.
3. **Gateway judge incomplete.** `gw` = gpt-5.6-luna. Repeats 1 and 2 are complete over all 477 cells; repeat 3 covers 49 cells, then three consecutive HTTP 429 ("main-account quota policy") stopped the run at 7.12M prompt tokens (budget 9M not reached; PLAN 36.4 stop rule). Cell J for `gw` is the mean of its valid repeats (2, rarely 3). 3 cells-repeats are recorded invalid (429), not imputed; no retry after the stop. Both Claude models: HTTP 401 "not logged in" -> no route (no login attempted). `gemini-3.6-flash` not listed -> no route.
4. **F builds** reused each domain's cached B-side work directory (copy of the Study 4 `work/`, including the LLM cache), as PLAN 36.5 says; the serving container is a different deployment of the extractor's model id (35.5).
5. Per-cell integer score for QWK = median-low of the valid repeats (PLAN 36.6, labelled).
