## 8.3 Step 1 -- external SHACL validation

For each domain with an official shapes graph (Brick, DCAT) and every variant A-F: `pyshacl.validate(data_graph=variant, shacl_graph=official shapes, ont_graph=official ontology, inference="rdfs", advanced=True)` (the official release's own import closure is loaded where shapes `owl:imports` ranges). Reported per variant: conforms, violation count (`sh:ValidationResult`, any severity counted separately: Violation / Warning / Info), top violated constraints (`sh:sourceConstraintComponent`, `sh:resultPath`, `sh:sourceShape`, top 5 by count), and **scope**: the number of focus nodes the shapes' targets select in that variant (`sh:targetClass` including `rdfs:subClassOf`-implicit class targets, `sh:targetNode`, `sh:targetSubjectsOf`, `sh:targetObjectsOf`; a shape that selects 0 focus nodes cannot be violated -- this is the vacuity of the external check on pipeline graphs whose IRIs live in `ct:`). Non-vacuity of the **official** shapes graph is documented separately from the data: counts of `sh:minCount >= 1`, `sh:class`, `sh:datatype`, `sh:nodeKind`, `sh:node`, `sh:in`, `sh:pattern` constraints, and of node shapes with a target.

Also reported: the paper's own `shapes_F.ttl` (Brick holdout, DCAT, SOSA/SSN, PROV, development): count of property constraints with `sh:minCount 0`, with `sh:minCount >= 1`, with `sh:nodeKind`, with `sh:datatype`, with `sh:class`, number of node shapes, and the result of validating F against it with `inference="rdfs"` (reproduces the released report).

Domains without official shapes (SOSA/SSN, PROV, development, second domain): reported as "no official shapes", with own-shapes statistics only (second domain: none, counts-only rule).

A variant that cannot be parsed or validated (error, timeout of 30 min per validation) is reported as such; nothing is imputed.

## 8.4 Step 2 -- domain/range quality against the official ontologies

Official ontologies: Brick 1.4.4 `Brick.ttl`, DCAT `dcat.ttl`, SOSA+SSN, PROV-O. Official domain/range of a property q: union of `rdfs:domain` / `rdfs:range`, `schema:domainIncludes` / `schema:rangeIncludes`, with `owl:unionOf` lists expanded to their members; the official hierarchy is `rdfs:subClassOf*` over the official ontology (`owl:equivalentClass` treated symmetric).

**Property mapping (pipeline property p -> official property q), three levels, each reported separately and all pooled with the highest level kept per p:**
1. *Alignment*: the domain's `standard_alignment.json` (pipeline verb label -> standard property IRI; null = unmapped) restricted to q that exist in the official ontology (alignment targets in other vocabularies, e.g. `dct:hasPart`, `skos:broader`, are counted as "aligned to a non-domain standard" and not compared).
2. *Exact IRI*: p's IRI equals an official property IRI (variant A graphs that use `sosa:`, `dcat:`, `brick:` terms directly).
3. *Local-name*: normalised local name of p (lower-case, non-alphanumerics removed, leading `p_` removed) equals the normalised local name or `rdfs:label` of an official property, also accepting official = p + "s", official = "has" + p, or p = official + "s" (a fixed list; nothing else).
A pipeline property that has a declared domain and range but no official counterpart is **unmapped**.

**Class identity.** A pipeline class c is *official-resolvable* if its IRI is an official class, or if its normalised local name / label equals the normalised local name or label of exactly one official class (after dropping a leading domain word such as `brick`). Generic stage classes such as `ct:Class_artifact` resolve to nothing and are labelled **non-comparable (generic class)** -- this is a result, not an error.

**Declared-level comparison** (variants C-F, and A where A declares domain/range; B declares none): for each mapped p with declared domain c: *exact* (c in official domain set), *subclass-compatible* (c resolvable and c subClassOf* some official domain member, or official domain is `owl:Thing`/`rdfs:Resource`), *broader* (an official domain member subClassOf* c; reported separately, counted as mismatch in the headline), *mismatch* (resolvable, none of the above), *non-comparable (generic class)*, *official undeclared* (q has no official domain). Same for range (datatype ranges: equal datatype, or c = `xsd:string`-vs-`rdfs:Literal` compatible when the official range is `rdfs:Literal`).

**Usage-level comparison (independent of the declared class):** for each mapped p, for every triple (s, p, o) in the variant where s (resp. o) is an entity that resolves to an official class by label/local-name as above (entity types from the graph are ignored), count whether that class is subclass-compatible with an official domain (resp. range) of q. Reported: n usage triples with a resolvable subject, compatible share; same for objects; share of usage triples with a resolvable end (coverage).

**Most-frequent-class artifact.** Per variant: class count (`owl:Class`/`rdfs:Class` IRIs, and classes used as `rdf:type` of entities); share of properties whose declared domain is the single most frequent declared domain; same for range; the most frequent class's share of typed entities.

Counts per variant: n properties with domain+range, n mapped (by level), exact / subclass / broader / mismatch / non-comparable / undeclared. Development corpus and second domain: class counts and most-frequent-class shares only (no official ontology; second domain counts only).

## 8.5 Step 3 -- provenance coverage (variants E and F; also D/C where PROV is absent, reported as 0 by construction)

Per domain and variant E/F: (i) concepts = subjects typed `skos:Concept` (entities); share with >=1 `prov:wasDerivedFrom`; (ii) chunks = the chunk set of that build (atomic chunks file of the build's work directory); share of chunks referenced by >=1 `prov:wasDerivedFrom` object; (iii) links per linked concept (mean, median, max); (iv) share of triples (excluding `prov:` and `dct:source` triples) whose subject is a concept with >=1 provenance link. Also the share of concepts with `dct:source` but no `prov:wasDerivedFrom`, to show whether provenance is lost between the two annotation styles.

**Link spot-check:** per domain, 30 (concept, chunk) `prov:wasDerivedFrom` links drawn at random from E (seed 20260913, `random.Random(seed)` over the sorted link list; if the domain has <30 links all are used); for each, does the chunk text contain the concept's label after normalisation (NFKC, lower-case, non-alphanumerics to single space, whitespace trimmed; labels = `skos:prefLabel` literals and the label recovered from the IRI local name; containment tested as normalised-substring on word boundaries)? Reported: share with contained, with the count; a looser reading (all content tokens of the label occur in the chunk, any order) as a second, labelled column. This tests string traceability only, not semantic correctness. Sample ids (concept IRI local name + chunk id) are written to `results.json` for Brick, DCAT, SOSA/SSN, PROV (public W3C/Brick text); for the development corpus and second domain only the shares are written (no ids, no text). The second domain has no E/F: reported "no PROV variant".

## 8.7 Limits stated in advance

External shapes are written for instance data in the standard vocabulary, whereas the pipeline emits SKOS concepts with `ct:` IRIs; a conforming result with few or zero focus nodes means "not tested", not "valid". Label-based class resolution is a heuristic with its own error; the usage-level numbers are lower-bound-style coverage figures. The string-containment spot-check is a necessary, not sufficient, condition for a correct link.
