# Study 8 - deviations and clarifications relative to PLAN.md (addendum 38)

AI-generated; review before reliance. None changes a number after seeing it for the purpose of a different conclusion; all are listed so a reader can re-run without them.

1. **Foreign nodes excluded from SHACL results.** Passing the official ontology as `ont_graph` makes pyshacl validate the ontology's own nodes too (Brick.ttl: 3 results on `ref:*Reference`). Results whose focus node is not a node of the pipeline graph are counted separately (`results_on_official_ontology_nodes_ignored`) and not counted as violations. Not stated in the plan; needed so that "violations" refers to the pipeline graph.
2. **Constraint-bearing scope.** Brick's release shapes contain 1,747 targeted shapes of which only 251 carry constraint components; the rest are inference-rule shapes (`sh:rule`). The plan's single "focus nodes" figure would have counted rule-only shapes as scope; both numbers are reported (`scope` vs `constraint_*`).
3. **DCAT-AP dangling references.** The 3.0.1 `dcat-ap-SHACL.ttl` has 2 `sh:property` links to nodes with no `sh:path` (5 with `ranges.ttl` added); pyshacl aborts when such a shape has a focus node (it did for variant A). A copy of the shapes without those links is validated; the number removed is in `external_shapes.<set>.dangling_sh_property_refs_removed_before_validation`; the files in `external/` are unchanged. DCAT is reported for two shape sets: core, and core + `ranges.ttl` (the plan named both files).
4. **Brick official domain/range.** Brick.ttl declares `rdfs:domain` for 1 and `rdfs:range` for 4 properties only; its constraints live in SHACL property shapes. For properties without rdfs/schema domain/range, the official domain/range is derived from the node shapes that carry `sh:property [sh:path q]` (holder class = domain, `sh:class`/`sh:datatype` = range). This follows the brief's "or the class of subjects/objects in the official ontology"; the source is tagged `shacl-derived` in code. The plan did not say this.
5. **Property set and local-name rule.** "Pipeline properties" = properties typed as property or with declared domain/range, plus every predicate IRI used in triples outside rdf/rdfs/owl/skos/prov/dct/xsd/sh. A local-name rule that hits more than one official property is reported as `ambiguous` and not mapped (the plan did not fix this).
6. **Stem-extended mapping (added, labelled).** Because verb labels rarely equal noun-like official property names, a post-plan sensitivity reading (`step2_stem_sensitivity`, crude suffix stripping, unique hit only) is reported next to the plan's levels. It never replaces them.
7. **Validation settings.** `pyshacl.validate(..., inference="rdfs", advanced=True)`, 30-min timeout (never reached), ontology graph as `ont_graph`; as in the plan.
8. **Scope of own-shapes check.** F validated against `shapes_F.ttl` with `inference="rdfs"` and no ontology graph (same call as study 7).
9. The development corpus (`output/`) and the second domain have no official ontology: step 1 and the official part of step 2 are "not applicable" there; the second domain is counts only and has no E/F (step 3 not applicable).
